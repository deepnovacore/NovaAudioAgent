# Nova Visor v1 — local macOS preview

[中文使用说明与架构扩展](VISOR_GUIDE.zh-CN.md)

Entry: Settings → Themes → Nova Visor. The orb-skin manager is now in Themes, directly below General.

## Implemented

- Primary-display transparent, non-focusable, mouse-through HUD above ordinary application windows. Menu bar and Dock work area are respected. No wallpaper replacement or desktop capture is needed for operation.
- Separate compact controls: show the existing Nova orb, Focus / Showcase, collapse. Tray and orb menu also toggle the HUD. `Cmd/Ctrl+Shift+J` toggles it; registration failure is logged and menus remain available.
- Four independently moving frame sections assemble, followed by instruments. Reverse collapse; motion toggle and OS reduced-motion preference. Core animation capped at 15 fps in Focus / 30 fps in Showcase; collapsing/destroying the HUD stops sampling; renderer visibility also gates core animation. OS occlusion/lock power behavior remains unverified.
- CPU interval utilization, used physical RAM including caches, home-volume occupancy, macOS battery/charging. Fast sampling every 2 seconds; disk and battery every 30 seconds. Unavailable metrics show a dash.
- Actual orb state, microphone state, configured active model, and current client-lifetime provider usage. Unsupported/missing usage is not fabricated. Costs show known priced portion and indicate incomplete pricing. The core is state animation, not a simulated microphone waveform.
- Independent persisted `nova-visor.json`; appearance changes do not restart the voice backend. Skin selection remains on the existing settings save flow. Imported skins remain data-only v1 orb skins; arbitrary full-desktop skin packages are not implemented.
- Sandboxed isolated renderers, dedicated minimal preload, no remote content, main-frame/sender checks for all new IPC, no keys passed to HUD.

## Validation, 2026-09-25

Iteration 1: production HUD controller and renderers in isolated Electron. Real OS telemetry; unavailable backend; screenshot alpha check; commands and preferences; rapid off/on sequence; all windows destroyed on collapse/disposal.

Iteration 2: real desktop click-through and typing tested with CUA against an underlying editable test window. Click changed the button to PASS and a complete pasted sentence was editable while the HUD stayed visible. Manual drag was attempted but position movement was not confirmed; do not count it as a passed check. Reduced motion, status vocabulary, frame mirroring and bright-background contrast refined.

Iteration 3: 255 scoped Node tests (skin, settings, protocol, preload, security, window positioning, telemetry, IPC authorization), full desktop build, packaged imports/native-resource validation, and local ad-hoc signature checks. Installed app launched using the existing encrypted profile and reached the original voice-ready state. A packaging-only Team-ID mismatch was found on a subsequent signed launch and corrected by the local-preview signer (production signing path unchanged).

The corrected signed installed process stays running without the earlier dyld error; final UI/backend readiness after that signing correction, Themes controls and the system shortcut remain unverified while the Mac is locked. Do not call this a completed production acceptance. Automated smoke is not evidence of a completed live-provider conversation. Windows/Linux, Spaces/fullscreen/multiple-monitor combinations and long battery/soak tests are not certified.

A short isolated Showcase performance sample (includes a separate test window) was ~2.7% summed Electron process CPU under Electron's metric convention; this is a spot measurement, not a long-run budget. Per-process raw measurements and screenshots are under ignored `output/visor-validation/` locally. Desktop screenshot contains the user's actual windows and is not committed.

## Reproduce

```sh
node --test clients/desktop/test/visor.test.mjs
clients/desktop/node_modules/electron/dist/Electron.app/Contents/MacOS/Electron clients/desktop/scripts/visor-smoke.mjs
npm run build --workspace @nova-audio-agent/desktop
```

For a local macOS preview, from `clients/desktop`:

```sh
CSC_IDENTITY_AUTO_DISCOVERY=false ./node_modules/.bin/electron-builder --config electron-builder.yml --config.electronDist=node_modules/electron/dist --mac dir --publish never
node scripts/sign-local-preview.mjs "$PWD/dist/mac-arm64/Nova Audio Agent Desktop.app"
```

This is an ad-hoc signed local development build, not a notarized public release. No Gatekeeper setting is changed. The native manifest is regenerated by the existing signing hook. The local CLI-managed app path contains this preview on the user's machine; a CLI update can replace it.

Original app and complete original profile were backed up under `~/.nova-audio-agent/local-build-backups/visor-20260925-042211/`. Quit Nova before restoring both. Do not commit that backup (it includes encrypted local configuration).

## Deliberate v1 limits

- Primary display only. Fullscreen apps: collapse manually if the overlay overlaps.
- Voice phrase “切换成 Jarvis” is not wired to a local theme action in this version; use Themes, menus or shortcut. Original voice interaction is retained.
- Independent original orb remains draggable in its prior location; bottom HUD core is a decorative state indicator. NOVA button reveals the original orb.
- GPU/temperature/fan/power and automatic app-aware placement are deferred. Widgets are not individually draggable yet.

Additional main-process startup probe: with an isolated profile, the actual app emitted `settings_ready`, confirming the settings renderer/sidebar check. It did not reach `source_window_ready` within 30 seconds during the locked-screen session; the native shown-stage check remains pending, and the probe was stopped cleanly. This is not counted as a full startup pass.
