# Headless remote service (macOS first)

By default (`NOVA_AUDIO_AGENT_SERVER_MEDIA_MODE=relay`), the Node service reuses
the desktop production composition, including model, Codex,
MCP, telemetry and lifecycle cleanup. Electron is not required. Remote sessions
force the native camera module off and expose only `/client/v1`; no debug board or
camera transport is available. Desktop still launches its own child service.

Stop the desktop instance before starting this service on the same host/project
state. Do not let two runtimes own the same writable workspace or state directory.
This service is not included automatically in existing desktop release packaging.

## Host platform scope

The current remote host credential and pairing stores require POSIX ownership and
0600/0700 permissions. Windows remote host storage is unsupported and is rejected
before creating a token or device state; Windows mode bits are not a substitute
for verified private DACLs. This restriction does not disable the Windows desktop
application or platform-independent client protocols. macOS remains the first
remote deployment target; Linux deployment requires its separate acceptance.
## Build and configure

Use Node >=22.13 and a checkout with its normal workspace dependencies installed.
Run builds serially with desktop work because both builds write `runtime/dist`:

```sh
cd /absolute/path/to/nova-audio-agent
npm ci
npm run build --workspace @nova-audio-agent/runtime
```

Create a private directory outside the checkout. Set these two required variables;
the port has no fallback and must be 1–65535. Missing/invalid values fail before
model, MCP or Codex resources are constructed.

```sh
mkdir -p "$HOME/.nova-remote"
chmod 700 "$HOME/.nova-remote"
export NOVA_AUDIO_AGENT_SERVER_PORT=19876
export NOVA_AUDIO_AGENT_SERVER_TOKEN_FILE="$HOME/.nova-remote/client-token"
npm run server:token-init --workspace @nova-audio-agent/runtime
```

Initialization creates a random 128-bit lowercase hexadecimal token with mode 0600
and refuses to overwrite any existing file. The loader rejects relative paths,
symlinks, non-regular files, foreign ownership and permissions other than 0600.
Use the QR pairing window described below for independent device credentials. Manual fallback: read the file locally and enter the token into the phone's Keychain-backed connection settings. Never place its contents in URLs, shell arguments, logs or Git.

Set model/executor configuration explicitly in a private environment file, for
example `$HOME/.nova-remote/server.env` (0600), using the existing Runtime environment
contract. This is a Node `--env-file` file, not a shell script; use absolute paths,
not `$HOME`/`~` expansion. At minimum choose/configure the desired pipeline and its
credentials. Codex additionally requires `NOVA_AUDIO_AGENT_EXECUTORS=codex` and an
absolute `NOVA_AUDIO_AGENT_CODEX_WORKSPACE`. Set
`NOVA_AUDIO_AGENT_CODEX_PROJECT_STATE_ROOT` to the intended private state directory.
The headless entry does not read Electron Settings or infer a project from cwd.
Codex login and any executable/resource-path configuration must be available to the
same macOS user running the service; a GUI application's environment is not inherited.

Remote v1 supports integrated Qwen, or cascaded Volcengine ASR/TTS with the existing
Qwen/Ark LLM selection. The adapters use mono PCM16 LE, input 16000 Hz and output
24000 Hz. Incompatible selections/output rates are rejected before resource setup;
ready is generated by ClientServer, not the legacy desktop bootstrap frame.

Start in the foreground first (include both server variables in the environment file
for unattended use):

```sh
node --env-file="$HOME/.nova-remote/server.env" runtime/dist/src/server-entry.js
```

Successful startup logs `[server-ready] ws://127.0.0.1:19876/client/v1`, with no token.
The service binds loopback only. An occupied port is an error; it never picks another
port. SIGINT/SIGTERM stop the owner, close the listener, then the realtime graph and
auxiliary resources. EOF on stdin or absence of an Electron parent does not stop it.

## AOQ pure-chat experiment

Set `NOVA_AUDIO_AGENT_SERVER_MEDIA_MODE=aoq_chat` in the private server environment
file and restart the service; omit it or set `relay` to restore the existing relay
pipeline. Other values fail configuration validation. The port and private token
file settings are unchanged. AOQ also needs `DASHSCOPE_API_KEY` (Beijing) and
`NOVA_AUDIO_AGENT_AOQ_API_HOST=llm-<workspace>.cn-beijing.maas.aliyuncs.com` on the server; missing or rejected API keys produce `credential_unavailable` on allocation.
No Runtime, provider, Codex or MCP graph is loaded/constructed in this mode. The
standalone broker binds only `127.0.0.1:<configured port>/client/v1`. It does not own
a workspace or accept host-control operations. Pipeline/executor settings do not
configure this experiment. Voice is selected by the server, default `longanqian`.

The client must advertise AOQ support in `hello`; incompatible media or protocol
versions close with 4006, invalid authentication with 4003. There is one active
connection (including authentication in progress); additional peers close with
4009. Authentication must finish within 3 seconds.

```json
{"type":"hello","token":"<private server token>","protocol_version":1,"media":{"transports":["qwen_aoq_chat_v1"]}}
```

Successful handshake (IDs are UUIDs):

```json
{
  "type": "client.ready",
  "protocol_version": 1,
  "server_instance_id": "<server UUID>",
  "connection_id": "<connection UUID>",
  "input_audio": {"encoding":"pcm_s16le","sample_rate":16000,"channels":1},
  "output_audio": {"encoding":"pcm_s16le","sample_rate":24000,"channels":1},
  "capabilities": ["audio", "captions"],
  "media": {"transport":"qwen_aoq_chat_v1","path":"direct","audio_owner":"aoq_sdk","pipeline":"integrated","mode":"chat_only"}
}
```

On the user's Start Voice action, the client sends exactly one credential request
per WS connection. `connection_id` must match ready and `request_id` must be a UUID.
Only these three fields are allowed; the client cannot select a URL, model, voice,
instructions or tools.

```json
{"type":"aoq.connect","connection_id":"<connection UUID>","request_id":"<request UUID>"}
```

The server calls only
`https://<workspace-api-host>/api/v1/webrtc/realtime?model=qwen-audio-3.0-realtime-plus`
with POST body `{}`, `Authorization: Bearer <DASHSCOPE_API_KEY>`,
`Content-Type: application/json` and `x-dashscope-rtc-transport: moq`.
There is no `clientIp`, custom endpoint or redirect following. The whole allocation
has an 8-second deadline, a 64 KiB streamed response limit and field validation.
The [official Token authentication document](https://www.alibabacloud.com/help/zh/model-studio/realtime-token-authentication)
shows a **top-level** response, not a `data` or `output` wrapper. Endpoint entries
have `endpoint`, `port` and optional `route_index`; the broker maps these to
`{endpoint, port, routeIndex: route_index ?? index}` for the iOS SDK, with 1–8 endpoints.
The complete outgoing JSON must be less than 16 KiB, otherwise allocation fails safely.
Only the allowlisted credential fields below are sent to the client. The upstream
`sidExpiresInSecs` is validated and used only to reject an allocation already expired
before delivery; it is not added to the wire. The official document calls it a
session expiration interval and says authentication occurs at connection setup,
but does not establish that the broker should terminate an already connected call
on this timer. Consequently there is no `expiryTimer` or implicit session cap;
after delivery, SDK/upstream connection state owns expiry and termination. Upstream bodies/errors are never logged or returned.

```json
{
  "type": "aoq.credentials",
  "connection_id": "<connection UUID>",
  "request_id": "<request UUID>",
  "credentials": {
    "aoqTokenForClient": "<temporary token>",
    "sid": "<session ID>",
    "clientRelayCertFingerprint": "<fingerprint>",
    "clientRelayEndpoints": [{"endpoint":"<relay address>","port":8443,"routeIndex":0}],
    "extraInfo": {"workspaceIdHash":"<workspace hash>"}
  },
  "session": {
    "modalities": ["text", "audio"],
    "voice": "longanqian",
    "input_audio_format": "pcm",
    "output_audio_format": "pcm",
    "instructions": "你是Nova，一个自然、友好的语音聊天助手。仅进行纯聊天，不执行主机工具，不操作文件、终端、项目或设备，也不声称已执行这些操作。",
    "turn_detection": {"type":"smart_turn"}
  }
}
```

Audio and captions travel through the client's AOQ SDK, directly to/from DashScope;
the broker does not forward PCM or provider events. All binary frames,
`client.command`, raw provider events and other JSON message types are rejected.
The iOS AOQ adapter applies the returned session over the SDK, starts capture only
after session.updated, and closes the SDK on WS loss, backgrounding or end-call.
The server cannot observe SDK-specific early token rejection; the client must
close/reconnect the WS after such a failure. No extra SDK-error wire is introduced.

Duplicate requests (even while pending), upstream failure, timeout, expired
allocations before delivery and exhausted allocation budget send the same secret-free frame,
then close with 4008:

```json
{"type":"aoq.error","code":"credential_unavailable"}
```

A fresh WS connection is required for another allocation. A process-local rolling
60-second budget allows at most 6 attempts across connections, including failures;
reconnecting does not reset it. Process restart resets the budget. Input JSON is
limited to less than 16 KiB; synchronous input bursts and outbound queues are limited to
128 messages and 256 KiB, with no queued inputs waiting behind allocation. Closing
peers are terminated after a 500 ms grace. Disconnect/shutdown aborts HTTP and
fences late results so they cannot reach a replacement connection. WebSocket
control ping runs every 15 seconds; a missing pong at the next interval terminates
the network connection (up to 30 seconds). These are WS control frames, not JSON.

Tests use injected HTTP/allocation responses and never request real credentials.
After the coordinating agent's serial build, run:

```sh
node --test runtime/dist/test/aoq-chat-server.test.js runtime/dist/test/server-entry.test.js runtime/dist/test/client-server.test.js
npm run typecheck --workspace @nova-audio-agent/runtime
```

## Private WSS with Tailscale

Install/sign in to Tailscale on the Mac and iPhone and restrict tailnet access to your
devices. On macOS, invoke the CLI bundled with the app and force CLI mode with
`TAILSCALE_BE_CLI=1`, including in non-TTY automation. This avoids the executable
selecting GUI mode based on shell environment; see the official
[macOS CLI guidance](https://tailscale.com/docs/reference/tailscale-cli?tab=macos).
Inspect the existing Serve configuration first:

```sh
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale serve status
```

For an unused HTTPS listener:

```sh
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale serve --bg --https=443 http://127.0.0.1:19876
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale serve status
```

Use `wss://<machine>.<tailnet>.ts.net/client/v1` on the phone. Keep the application
token in the authentication frame. Use Serve, not public Funnel. See the official
[Tailscale Serve CLI reference](https://tailscale.com/docs/reference/tailscale-cli/serve)
for HTTPS prerequisites and listener management. To remove this dedicated listener
(do not remove another service's shared listener):

```sh
TAILSCALE_BE_CLI=1 /Applications/Tailscale.app/Contents/MacOS/Tailscale serve --https=443 off
```

## launchd

After foreground validation, save a per-user LaunchAgent at
`~/Library/LaunchAgents/com.nova.remote.plist`. Replace every absolute placeholder;
launchd does not expand shell variables. Keep the environment file outside Git and
place credentials there, not in the plist. Create the log directory first.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.nova.remote</string>
  <key>ProgramArguments</key><array>
    <string>/absolute/path/to/node</string>
    <string>--env-file=/Users/your-user/.nova-remote/server.env</string>
    <string>/absolute/path/to/nova-audio-agent/runtime/dist/src/server-entry.js</string>
  </array>
  <key>WorkingDirectory</key><string>/absolute/path/to/nova-audio-agent</string>
  <key>RunAtLoad</key><true/>
  <key>StandardOutPath</key><string>/Users/your-user/.nova-remote/server.log</string>
  <key>StandardErrorPath</key><string>/Users/your-user/.nova-remote/server.log</string>
</dict></plist>
```

```sh
plutil -lint "$HOME/Library/LaunchAgents/com.nova.remote.plist"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.nova.remote.plist"
launchctl print "gui/$(id -u)/com.nova.remote"
# Stop and unload before maintenance or credential rotation:
launchctl bootout "gui/$(id -u)/com.nova.remote"
```

There is deliberately no KeepAlive restart loop. A service exit needs diagnosis and
an explicit bootstrap; a new process does not restore unfinished work or approvals.
A LaunchAgent requires the user's login session; Linux and unattended system-daemon
operation remain separate acceptance work.

## Credential rotation and recovery limits

P1 implements operational rotation, **not live token reload/revocation**:

1. Stop/unload the service and confirm its process and listener have exited. This
   disconnects old clients and stops graph-owned work; arrange downtime first.
2. Remove only the configured token file, then run `server:token-init` again with the
   same absolute `NOVA_AUDIO_AGENT_SERVER_TOKEN_FILE`.
3. Update the phone credential and restart/bootstrap the service. Old credentials
   cannot authenticate to this new process. Editing a token file while running has
   no effect on the current process or its active connection.

Within the same process, a transport send failure, queue overflow or phone network
disconnect releases/fences that connection rather than aborting the graph. Reconnect
receives current project/executor/approval state and retained bounded results;
old audio is discarded. Request receipts acknowledge delivery only: host state owns
approval and execution truth. They do not prove a task completed.

Provider failures still follow the existing realtime lifecycle owner and may close
the graph/Codex resources. Transport tests do not prove provider-failure task survival.
Process restart changes server identity, invalidates in-memory approvals and does
not resubmit or resume unfinished commands. Explicit shutdown likewise makes no
promise that a running Codex task survives.

## Diagnosis and acceptance

Exit code 2 with `configuration_required` means check token path/owner/mode, fixed port
and model/executor configuration locally. Other startup failures use stable diagnostics
such as `assembly_failed` or `backend_unavailable`; inspect `lsof -nP -iTCP:19876 -sTCP:LISTEN`
for a port conflict. Never paste credentials into a bug report.

Focused automated checks cover headless lifecycle, configuration before allocation,
private token creation, rollback, transport overflow/send failure and stale callbacks.
Real model/Codex execution through Tailscale, credential rotation on an actual service,
Wi-Fi/cellular recovery, iPhone audio/AEC and lock-screen behavior require separate
acceptance evidence. This document is deployment guidance, not a claim those gates passed.

Remote Stop or an abrupt client disconnect discards unfinished microphone input by replacing
only the realtime provider session. New PCM waits for replacement; if replacement fails,
input stays closed until a later disconnect/reconnect successfully replaces the provider.
If voice remains unavailable after a transient provider failure, use Stop and connect again
to retry without restarting the host or running Codex work. Provider-bound proposals and approvals are invalidated by the existing
session-replacement policy. The host graph and running Codex work remain alive; this does
not provide persistence across a server process restart.


### Reuse the desktop keychain (local convenience launcher)

The old `dashscope.aliyuncs.com` endpoint does not support AOQ. Supply the Beijing workspace API Host shown in the official console, without a scheme, port, path or query. The broker validates the complete host against `llm-[a-z0-9]+.cn-beijing.maas.aliyuncs.com`, builds the fixed HTTPS allocation path, and forbids redirects. No client message can change the host.

For a Mac that already stores its DashScope key in Nova's encrypted desktop settings, this optional launcher uses the existing safeStorage codec in memory; the production Node broker itself remains independent of Electron. Build runtime first, stop the old listener, then run:

```sh
NOVA_AUDIO_AGENT_SERVER_MEDIA_MODE=aoq_chat \
NOVA_AUDIO_AGENT_SERVER_PORT=19876 \
NOVA_AUDIO_AGENT_SERVER_TOKEN_FILE="$HOME/.nova-remote/client-token" \
NOVA_AUDIO_AGENT_AOQ_API_HOST=llm-YOUR_WORKSPACE.cn-beijing.maas.aliyuncs.com \
clients/desktop/node_modules/electron/dist/Electron.app/Contents/MacOS/Electron \
  clients/desktop/scripts/aoq-server.mjs
```

Use the actual lowercase workspace host. The launcher neither exports keys to files nor sends them to a renderer. Stop it before starting the normal `relay` service. macOS may require user interaction to allow access to the already saved keychain item.

### AOQ with Nova Runtime

Set `NOVA_AUDIO_AGENT_SERVER_MEDIA_MODE=aoq_runtime` to enable tools, project state and approvals over the AOQ control connection. `relay` remains the server default; the keychain convenience launcher defaults to `aoq_runtime`, with an explicit `aoq_chat` override for standalone chat. Mode changes require a service restart. The phone's AOQ setting offers both modes; the authenticated server selects one explicitly.

Runtime mode requires the same Codex configuration as the ordinary remote service: an absolute canonical `NOVA_AUDIO_AGENT_CODEX_BIN`, existing `NOVA_AUDIO_AGENT_CODEX_WORKSPACE`, validated native resources via `NOVA_AUDIO_AGENT_CODEX_RESOURCES_PATH`, and a capabilities configuration with coding enabled. Keep the existing approval mode. Do not reuse a voice-only test capabilities file that disables coding. Supply the existing support-model configuration as well as the DashScope key. In a source Mac checkout, the native resource root is `clients/desktop/build`; use its matching Electron runtime with the keychain launcher, as native resources are ABI-bound.

AOQ Audio stays on the phone. Data events and host commands use the private WSS connection and the existing Runtime/Qwen tool path. The listener starts before provider readiness so the phone can attach; `server-ready` proves only that the control listener exists. `aoq_provider_connected` confirms the SDK session/configuration handshake. A failed attachment logs `aoq_handshake_failed`, releases that phone and waits for a new connection.

Phone disconnection preserves the host graph and authorized background work while fencing the old provider session. Recovery requires reconnecting and pressing Start voice; it is not transparent audio recovery. Server shutdown still stops the graph. No synthesized playback/"heard" receipts are produced; use the displayed host confirmation cards for explicit project/execution decisions. Actual SDK response-to-playback correlation remains separate work.

## 扫码配对与设备撤销

运行新版服务并保留相同的环境配置，在 Mac 执行：

```sh
npm run server:pair --workspace @nova-audio-agent/runtime -- wss://你的主机.ts.net
```

窗口提供二维码、有效期、已配对设备和撤销按钮。手机在 Nova 的连接设置选择“扫码连接主机”，确认地址后即可保存并连接。此入口适用于 Relay、AOQ Chat 和 AOQ Runtime，旧手填配置继续可用。主机长期 token 只通过子进程 stdin 和 loopback 管理连接传递，不进入二维码、进程参数、日志或图片文件。

配对使用现有端口的 `/client/pair` WebSocket；管理窗口使用 `/client/pair-admin`，每个管理请求都必须携带原有主机 token，设备 token 无管理权限。Tailscale Serve 需代理整个服务（包括这两个路径和 `/client/v1`），仍使用系统 TLS 校验。配对连接不占用音频连接名额、不构造 AOQ 会话或触发 Runtime 工具。

服务把设备 ID、名称、创建时间和 token 哈希原子写入 `${NOVA_AUDIO_AGENT_SERVER_TOKEN_FILE}.devices.json`（0600），最多 32 台。请继续将 token 及其设备文件放在 0700 私有目录，并保证单个服务进程拥有此目录。不可让多个实例共写设备文件。服务拒绝非私有、损坏或与主机 token 不匹配的设备文件；不要在运行中编辑文件。轮换主机 token 时，停止服务并同时移走旧设备文件，重新初始化、启动后重新配对手机。

二维码有效期为 120 秒，只有一次兑换机会；刷新使旧码失效。关闭窗口取消尚未兑换的码，异常退出依靠到期失效。兑换响应丢失会留下可在窗口中撤销的设备记录，重新扫码即可。撤销独立设备不会影响其他设备凭据；手填共享主机 token 的连接需要轮换主机 token 才能整体撤销。
