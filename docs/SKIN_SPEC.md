# Nova 自定义皮肤规范

状态：**v2 设计草案，尚未实现，不能直接导入当前客户端。**

当前 `codex/orb-skins` 仅实现 v1：单个 JSON、`particle-core` 渲染器及颜色/粒子数量/旋转速度参数，详见 [现行说明](../skins/README.md)。本文定义下一阶段作者交付格式和验收边界；参数预算为拟议上限，不代表已经完成性能验证。正式冻结前需要实现 JSON Schema、校验器、渲染器和验证工具。

## 1. 职责边界

皮肤负责视觉图层、素材、动画和对真实状态的视觉响应。Nova 负责语音、状态判断、任务执行、权限、菜单、拖拽、点击区域、窗口大小和可访问性标签。

皮肤只能读取宿主提供的状态与归一化音量，不得到录音、聊天内容、密钥、文件访问或网络能力。错误/闭麦标识由宿主最后绘制，皮肤不能覆盖。皮肤不能自行把错误改成成功、伪造任务进度或改变交互按钮含义。

v2 首期目标是自定义悬浮球的形状与动画。驾驶舱窗口、任务区域布局、全屏展开和语音切换命令需要另外的宿主功能；皮肤可以声明内部图层的位移/旋转/缩放，但不能自行创建这些界面或命令。

## 2. 作者交付文件

包扩展名拟定为 `.nova-skin`，内容为 ZIP，以下文件位于包根目录：

```text
my-skin.nova-skin
├── manifest.json      # 必需：身份、版本、兼容性、入口及文件清单
├── scene.json         # 必需：视觉图层和可调参数
├── states.json        # 必需：状态表现、动画、信号绑定和降级表现
├── preview.png        # 必需：512×512 静态透明预览
├── LICENSE.txt        # 必需：作者声明及皮肤/素材的使用许可
├── assets/            # 可选：被引用的 PNG/WebP 图像或精灵图
│   └── shell.webp
└── CREDITS.md          # 使用第三方素材时必需：作者、来源、许可与修改说明
```

纯程序绘制皮肤只需前五个文件，不必提供 `assets/`。不要求作者提供 JS、CSS、HTML、依赖安装文件或可执行程序。验证报告由 Nova 验证工具生成，不接受作者自填的“通过”字段作为验收结果。JSON Schema 随开发工具发布，不由皮肤包自行定义或替换。

### manifest.json

| 必填字段 | 含义与约束 |
| --- | --- |
| `schemaVersion` | 固定为 `2`，与皮肤自身版本分开 |
| `id` | 稳定 ID：1–48 位小写字母、数字、连字符，字母开头；`nova` 保留 |
| `name` | 1–64 字符展示名，无控制字符/方向覆盖字符 |
| `version` | 皮肤版本 `major.minor.patch`，三个非负整数 |
| `author` | 1–80 字符作者展示名 |
| `description` | 1–280 字符简介 |
| `engine` | 固定为 `scene-2d`，由客户端实现 |
| `minSkinApi` / `maxSkinApi` | 支持的皮肤 API 整数版本范围；校验当前宿主 API 是否在范围内 |
| `entry` | 固定引用 `scene.json`、`states.json`、`preview.png`、`LICENSE.txt` |
| `files` | 除 manifest 自身以外的所有包文件清单，每项包含相对 `path`、`bytes`、`sha256` |

文件清单用于完整性校验，**不证明作者身份或官方审核通过**。重复 ID 的同版本内容差异视为冲突；替换/升级必须在预览中明确显示并由用户触发，不能静默覆盖。名称和描述始终作为文本展示。

## 3. 视觉参数和图层

统一逻辑画布为 116×116，中心为 (58,58)，宿主负责实际像素比和缩放。最终绘制裁剪在宿主圆形区域内，不允许改变点击区域。每层必须有唯一 `id` 和明确 `type`；图层数组顺序决定绘制顺序。

| 参数组 | 作者可配置内容 | 拟议约束 |
| --- | --- | --- |
| 基础配色 | 主色、装饰色、背景色 | `#RRGGBB`；透明度单独用 0–1 数值 |
| 图层结构 | `group`、`sphere`、`ring`、`arc`、`particles`、`image`、`sprite` | 总节点 ≤32，嵌套深度 ≤4；未知类型拒绝 |
| 通用变换 | `x`、`y`、`scale`、`rotation`、`opacity` | x/y：−116–232；scale：0–2；rotation：−360–360 度；opacity：0–1 |
| 圆/弧几何 | `radius`、`strokeWidth`、`startAngle`、`sweepAngle` | 半径 0–58；线宽 0–8；起角 −360–360 度，扫角 0–360 度 |
| 球体 | 半径、颜色、透明度 | 半径 0–58；不开放任意 shader |
| 粒子 | 数量、尺寸、分布、旋转速度 | 全场景 ≤600；尺寸 0.2–3；分布枚举 `sphere`/`disc`；速度 −1–1 rad/s |
| 光晕 | 色彩、强度、半径 | 强度 0–1，半径 0–16；须缓存，不允许无限叠加实时模糊 |
| 图像 | 素材 ID、宽高、适配方式 | 只引用文件清单内资产；宽高 0–116；适配 `contain`/`cover` |
| 精灵图 | 素材 ID、帧宽高、帧数、播放率、循环 | 等大网格，整数帧宽高/帧数且不越界；帧数 ≤120，播放率 1–30 fps |
| 动画 | 属性关键帧、时长、缓动、循环 | 仅数值型变换/几何/透明度属性；时长 100–10000 ms；每轨 ≤16 关键帧、同时 ≤16 轨 |
| 缓动 | `linear`、`ease-in`、`ease-out`、`ease-in-out` | 使用宿主内置实现，不执行表达式 |

`scene.json` 必须包含 `canvas`、`tokens`、`layers`。每种图层只接受该类型的属性；不使用的参数不必填写，默认值必须由对应 JSON Schema 固定。颜色不做 v2 首期关键帧插值。超限数据必须报错，不能静默截断成另一种皮肤。

## 4. 状态、信号与动画协议

`states.json` 必须包含以下字段：

- `base`：基准属性值，所有状态从此重新计算，不能继承上一个状态的残留值。
- `presets`：至少覆盖 `booting`、`inactive`、`idle`、`candidate`、`listening`、`speaking`、`muted`、`disconnected`、`reconnecting`、`error` 十个预设。每个预设允许属性覆盖及进入/循环动画；错误细分状态可额外定义。
- `overlays`：`codexWorking` 活动覆盖层，只表示任务进行中，不接收或伪造完成百分比。
- `bindings`：宿主信号到属性的声明式映射，可为空数组。
- `accessibility`：必须包含 `reducedMotion` 和 `highContrast` 的静态表现定义。

状态源以 `clients/desktop/src/renderer/state.mjs` 导出的 `ORB_STATE_NAMES` 为准。`permission-denied`、`microphone-restricted`、`microphone-no-device`、`microphone-busy`、`microphone-unavailable`、`audio-pipeline-error`、`configuration-required`、`authentication-failed`、`backend-unavailable` 使用显式预设，或由宿主映射至 `error`。新增的未知状态回退 `error`，同时保留宿主真实文字说明。

信号白名单：

| 信号 | 来源/规则 |
| --- | --- |
| `micLevel` | 宿主提供 0–1，仅 `listening` 时可用，其他状态为 0 |
| `playbackLevel` | 宿主提供 0–1，仅 `speaking` 时可用，其他状态为 0 |
| `codexWorking` | 宿主布尔值，只控制活动覆盖层 |
| `interrupt` | 宿主触发的短暂动画事件，不具有语音控制能力 |

数值绑定必须指定目标图层、允许的目标属性、输入信号、输出 `min`/`max` 和 0–1000 ms 平滑时间；输出不得突破属性限制。同一状态内，一个属性只能有一个动画或信号驱动源，冲突拒绝。没有真实音量时必须回到基线；装饰性呼吸动画可以存在，但不得冒充声波/任务进度。

状态变化取消旧状态的动画并恢复 `base`，再应用新状态和覆盖层。中断事件不可覆盖宿主闭麦/错误标识。切换、隐藏和销毁由宿主管理；减少动态效果时取消循环及事件动画，保留静态语义；高对比度时以宿主可访问性外观为最终保障。

## 5. 包校验和加载规则

拟议限制：ZIP ≤5 MiB，解压后总量 ≤16 MiB，文件 ≤64 个；单个 JSON ≤128 KiB；单张图片宽高 ≤2048，所有解码图片合计 ≤8 百万像素。必须同时检查压缩、解压与解码预算，不能只信任文件头。

拒绝绝对路径、`..` 路径段、反斜杠、符号链接、嵌套压缩包、同路径重复项、大小写冲突项、清单未列出文件和缺失引用。入口名称固定，其余文件名使用 ASCII 字母/数字/连字符/下划线及目录分隔符；允许文件类型仅为规范列出的 JSON、PNG、WebP、TXT、MD。图片要求静态，动画使用受控精灵图；v2 首期不接受 SVG、GIF、视频、字体、3D 模型、外部 URL 或脚本。

导入顺序：临时目录解包 → 文件/Schema/引用/预算校验 → 图片实际解码 → 隔离预览 → 用户应用 → 原子安装并保存选择。失败不改变现用皮肤；升级失败保留旧版本。安装位置由宿主决定，包内路径不能控制文件系统写入位置。v1 导入保持兼容，不能把 v1 文件当 ZIP 解压。

## 6. 什么叫“过审”

区分两个结果：**可安装**表示本机校验通过；**官方收录**表示自动检查和人工体验评审均通过。用户自行导入不应等待人工审核，也不能自动展示“官方认证”。

| 检查 | 通过条件 | 证据 |
| --- | --- | --- |
| 格式与资源 | 必要文件齐全，Schema、清单哈希、版本、引用及预算全部通过 | 工具生成结构化错误/通过报告 |
| 状态完整性 | 每个真实状态都有映射；错误、断连和闭麦不显示为健康待命 | 全状态截图及转换测试 |
| 实际交互 | 皮肤不遮挡菜单/文字，不更改拖拽/点击含义；录音/播放反馈跟随宿主 | 宿主集成测试 |
| 生命周期 | 连续切换 100 次后无遗留定时器/监听器；隐藏时停止动画；故障可回退 | 自动化计数与失败注入报告 |
| 可访问性 | 减少动态效果停止运动；高对比度、闭麦/错误静态标识清晰；不只靠颜色区分状态 | 模式截图与人工检查 |
| 性能 | 默认静止待命 ≤15 fps，活动 ≤30 fps；停止/隐藏无动画帧；最差状态不得持续掉帧 | 标明硬件、系统、宿主版本、分辨率和采样时长的报告 |
| 视觉质量 | 98px 实际显示尺寸和 1×/2× 下仍清楚；无裁切、错误闪烁、遮挡或明显锯齿 | 原尺寸截图与状态切换录屏 |
| 分发说明 | 作者/版本/许可齐全；第三方素材有来源；预览与实际表现一致 | LICENSE、必要时 CREDITS、人工评审 |

性能初始验收目标：在指定基准机上分别采集 idle/listening/speaking 各 60 秒，皮肤绘制耗时 p95 ≤4 ms，预热后 10 分钟循环不能持续增长内存。基准硬件和允许的内存波动阈值须在实现阶段实测冻结；未冻结前只能标注“功能验证通过”，不能声称已完成跨设备性能认证。官方收录报告记录包 SHA-256，任何内容更新都需要重新验证。
