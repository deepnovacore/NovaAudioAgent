# 设计约束

以下约束用于保证实时对话持续响应，同时让后台能力可以独立扩展和替换。

| 方面 | 约束 |
|---|---|
| 调度 | 按顺序处理事件，模型调用和执行器任务异步运行。 |
| 状态 | 先更新运行时记忆，再生成回复；不以模型服务端的对话历史为准。 |
| 发言 | 只有 FrontBrain 通过 Floor 向用户说话；Nova 可以中断自己的播放，不能打断用户。 |
| 提醒 | Proactive 评估后台建议，不充当第二个对话智能体。 |
| 执行 | 通过清单、适配器和控制器扩展能力，不在 Runtime 中增加特定能力的分支。 |
| 授权 | 宿主掌握审批和项目身份；模型输出不能授予权限。 |
| 上下文与证据 | 模型只接收受限上下文；检索文本和图像始终按不可信证据处理。 |
| 隔离 | 文档知识、个人记忆和当前任务状态相互独立；桌面渲染进程使用沙箱和受限的预加载接口。 |

新增能力需要遵守这些边界。通用工作流语言、无限制的记忆检索、跨执行器事务和多角色同时发言不在当前范围内。设备和执行器不能自行扩大权限。
