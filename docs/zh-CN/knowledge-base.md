# 知识库

导入自己的文档，让 Nova 检索并引用其中的内容。知识库与个人记忆相互独立：它只存放你主动导入的文档，不收录从对话中提取的信息。

## 开启模块

该模块默认关闭。可在设置面板开启，或在 `~/.nova-audio-agent/capabilities.json` 中设置 `modules.knowledge.enabled`。生成向量需要 DashScope 凭据。

## 导入文档

在电脑的知识库面板中操作。添加文件、添加文件夹、添加网址、移除来源和重建索引都属于宿主操作，模型无法代你导入或删除。

| 来源 | 说明 |
|---|---|
| 文件 | 文本、Markdown、HTML、PDF 和 Word（`.docx`） |
| 文件夹 | 导入其中受支持的文件 |
| 网址 | 仅限公网地址，内网和回环地址会被拒绝 |

每份文档会切分为约 800 token 的重叠片段，能识别标题的格式会沿标题切分。单个知识库最多容纳 100 个来源、20000 个片段。

导入不是瞬时完成的。面板会列出各个来源并提示失败任务；请检查文件格式、下文的敏感内容规则或服务连接后重试。

## 数据流向

片段存储在本地 `~/.nova-audio-agent/knowledge.sqlite`（可用 `KNOWLEDGE_PATH` 覆盖）。

**本地存储不等于本地处理。** 为了让文档可被检索，其文本会发送到配置的 embedding 服务，默认是 DashScope `text-embedding-v4`。请只导入你愿意发送过去的文档。疑似凭据的内容会在存储和发送之前被拒绝。

## Nova 如何使用

只有在需要时 Nova 才会检索知识库，不会自动把内容注入每一轮对话。检索结合语义匹配与关键词匹配，结果被当作**证据而非指令**，文档无法指挥 Nova 执行操作。

当 Nova 把编码任务交给 Codex 时，可能附上简短的片段作为参考。引用锚定在片段的具体内容上，因此你修改或移除来源后，旧引用会明确报告已过期或已失效，而不会悄悄返回错误内容。

也可以选择把知识库开放给 Codex，让它直接查看被引用片段的完整内容。Codex 仍然无法修改知识库。

## 使用限制

检索质量取决于 embedding 服务。移除来源会删除其片段，但无法撤回已经发送出去的文本。重建索引会重新发送文档内容。
