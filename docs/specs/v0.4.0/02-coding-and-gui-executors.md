# 05 Coding 与 GUI 执行器

> 轨道 D。v0.4.0 明确目标：接入 Kimi Code 与 pi agent；接入 GUI 执行器，
> 以 AutoGLM 作为首个 example；用真实闭环展示 agent2agent 协作。
> 状态：规划，未实现、未验收。里程碑 M9 保留编号，移自 v0.3.0；不等待 M8。

## 1. 复用边界

沿用 v0.2.0 的 07 执行器边界 与
08 coding 调度。FrontBrain 仍表达用户意图，
主机持有工作身份、授权与交付；coding controller 拥有 workspace/session 选择与调度。
不得把后端的原生工具、会话状态机或具体 API 暴露成一组新的快脑原生工具。

现有 Codex 实现是参考，不是假定其他后端有同样能力的依据。Kimi Code、pi agent 的
具体仓库/发行版本、接入方式与许可证在实现前固定；本规划不预设其支持 app-server、
steer、resume 或网络审批回调。AutoGLM 参考副本也不等于可运行集成。

## 2. Kimi Code 与 pi agent（M9-C）

两个后端分别交付适配器，复用既有 coding 角色与 WorkOrder，不另造调度器。

- 用户在设置中选择 coding 后端；活动工作绑定启动时的后端与会话。切换默认后端不迁移正在运行的工作。
- 同一工作区的并发/互斥仍由已有调度规则管理。不同后端的 session ID 必须按后端隔离；
  不把 Codex session 直接传给另一个 agent，也不承诺自动搬迁历史。
- 统一表达 run、进度、最终结果、失败、取消及清理完成。对不支持的 steer/resume 等能力
  明确禁用并解释，不用新开任务冒充原任务继续。
- 审批请求必须带 originating work、动作和范围，走现有 host broker；拒绝、过期、
  断连不能变成允许。后端无法提供所需沙箱与审批能力时，不开放依赖该能力的执行模式。
- 凭据与进程环境按现有主机边界管理；日志、进度与结果继续脱敏。

每个后端先填写能力矩阵：启动/认证、工作区、会话恢复、运行中补充、取消、审批、
沙箱/网络限制、进度、退出清理、支持平台。列明原生支持、宿主适配或不支持，并给测试证据。
具体传输方式在该矩阵核实后选择，不先增加通用多 Agent 框架。

**退出条件：** 每个后端独立完成“请求修改示例仓库 → 必要审批 → 修改 → 运行验证 →
返回产物与限制”的真实闭环；覆盖拒绝、取消、进程崩溃、凭据失效和会话恢复/明确不支持。
Codex 原有回归仍通过。后端 A 的成功不能替代后端 B 的验收。

## 3. GUI / AutoGLM example（M9-G）

新增 GUI 角色的 agent executor，AutoGLM 是第一个实现；与已有只负责观察的 Vision /
Camera / watch / guard 区分。首版选定一个真实设备平台、一个目标应用与可回滚场景，
再固定支持矩阵；不提前声称同时支持电脑和手机的全部 GUI 操作。

- 绑定明确设备、应用与当前工作；独占控制或明确返回 busy。截图和观察结果为低信任证据。
- 用户批准的是目标和操作范围。发送、付款、删除等有外部影响的动作在执行前按策略确认；
  对话里提到某个动作、图片里的文字或个人记忆均不是授权。
- 通过既有 dispatch/cancel 与进度/结果路径接入；取消后停止后续设备动作，清理控制权。
  外部操作状态不明时返回“未确认”，先核验再重试，避免重复发送或重复提交。
- 结果包含实际完成的步骤、可展示的证据和未完成部分；仅有模型“成功”文本不算执行成功。
- 设备离线、权限缺失、界面变化、控制权冲突必须可见并安全结束或请求用户接管。

**退出条件：** 真机完成一次用户请求驱动的 GUI 工作、一次拒绝和一次中途取消；
验证设备操作确实停止、证据与结果一致，说明目标平台和不支持项。

## 4. agent2agent 演示与发布材料（M9-Demo）

agent2agent 指 Nova 委派工作给 coding/GUI 专长 agent，并接收受约束的进度和结果。
它不自动代表实现某个名为 A2A 的协议；若要宣称协议兼容，另列版本与互操作验收。

演示使用合成数据，保留自然语言请求、授权记录、执行片段、最终结果和失败路径：

1. Nova → Kimi Code / pi agent → 示例仓库产物，每个后端单独演示。
2. Nova → AutoGLM → 指定设备上的可回滚操作，包含必要确认与可验证结果。
3. 可选联动：用户确认记忆驱动的建议后才进入执行；不把“主动发现需求”剪辑成“未经授权自动执行”。

发布材料包括后端/模型版本、平台、配置说明、真实录屏、复现步骤、支持矩阵与限制。
M9-Demo 依赖 M9-C 和 M9-G 各自验收；宣传文案不得先于对应能力。
Home Assistant 和更多后端留作后续扩展，不占本版三项主线的验收名额。
