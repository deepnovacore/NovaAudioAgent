# 04 来源与 connector

> 轨道 C。目标：用户自己决定 Nova 能读哪些目录和账户；Nova 在范围内持续、增量地了解变化，
> 形成有来源的记忆和有依据的发现；覆盖范围、失败与同步状态对用户可见；撤销和删除能传播到
> 检索、记忆与建议。写操作是可选能力，走既有执行授权路径。

M8-IM（飞书连接器，§2.5）为规划，2026-09-12 决定留在 v0.3.0，推翻 09-11 移至 v0.4.0 的划分。执行生态 M9 仍在

## 2. 本卷新增

### 2.1 Connector 通用层

一个 connector 同时服务两个场景：用户按需查询（工具）和后台增量同步（来源记录）。共享账户、
权限与 provider 实现。M8-Mail 首版只交付后台同步，按需远程查询延后；不新增前脑工具面。

通用层负责：连接状态（`connected | paused | disconnected | error`）、凭据引用（凭据本体只由主机
持有，模型与 renderer 不得到原始 token）、同步进度（provider cursor）、重试与配额、
最近同步时间与错误。Provider adapter 保留领域语义（邮件线程、日历重复规则），不把一切压成纯文本。

**来源记录**就是 06 卷的 `evidence_record`：连接器只做一件事，把变化写成账本行（原文、账户、原始 ID、
游标、时间、定位符）。它是 02 卷 `evidence_refs` 与 03 卷 `source_refs` 的引用目标。连接器必须提供
**可重放的游标**，不能只给增量差分；原文保留期（`retention_until`）是每个连接器的配置项，
IM 原文默认 30 天；邮件按接收时间保留 30 天，日历按事件结束时间再保留 30 天，本地目录默认长期。

MCP 是工具暴露方式。可复用现有 MCP server 作为查询工具，但**只提供搜索工具不等于具备持续同步能力**。
判定标准：能否稳定分页、能否给出变更（新增 / 修订 / 删除）、能否从中断处恢复。不满足则只作为按需
查询工具接入，不产生来源记录。

### 2.2 本地目录（M7）

- 用户在设置中选择允许的目录；每个目录独立开关。默认不选任何目录。
- **元数据概览先行**：先扫描范围内的路径、类型、大小、修改时间，形成概览；正文按相关性、近期变化和
  预算（每次同步的文件数与字节上限，待评审）选择性读取。
- **排除**：敏感路径（凭据、密钥、浏览器配置等模式列表）、缓存、依赖目录（`node_modules`、
  `.git`、构建产物等）默认排除且用户可见；符号链接解析后重新验证是否仍在允许范围内。
- **增量**：监听或轮询变化；启动与恢复后做一次补充核对。删除的文件传播为来源删除。
- **可见性**：设置中显示已扫描文件数、已读正文数、跳过数与原因、解析失败列表、上次同步时间。
  只处理部分文件时不得宣称"了解了整台电脑"。
- 元数据与路径本身是受控内容：不进入遥测；进入模型时受同样的低信任约束。
- 复用知识导入的解析与分块。预算内读到的正文先写 06 卷 A 账本，再建立派生索引并供 B 抽取；元数据概览不能替代正文。当前 M7 已调用 Knowledge 同步，后续收敛其原文归属和 canonical evidence_id，不重复建设索引。
- 目录读取许可与模型/embedding 外发许可分别校验；只有明确覆盖该目录和 provider 的同意才允许外发，未授权仍可本地词法检索。删除文件同时撤回 A 依据、索引和仅依赖它的记忆。

### 2.3 邮件与日历（M8-Mail）

以**一个**服务商生态验证闭环再扩展。2026-09-19 已确认 Composio + Gmail / Google Calendar，先只读后台同步；详细设计已批准（本地文档），固定版本契约已完成探针验证；实现与 live 层级见本地验收记录。

- **日历**：保留事件 ID、日历归属、时区、全天语义、重复规则与例外、取消状态。
- **邮件**：保留消息 ID、线程归属、参与人、时间、正文及必要状态。"是否待回复"需检查线程，
  不由一封历史邮件决定。
- **同步**：初次同步明确范围（时间窗、标签 / 日历选择）；后续保存 provider cursor。变化与 cursor
  的持久化必须保证失败后可安全重试。Google Calendar v1 先用有界窗口快照核对；syncToken 接口已探针确认，非空增量生命周期验收后再启用；
  Gmail 用 historyId，历史过期时恢复同步；Microsoft Graph 后续可用 delta 适配。
- **删除与取消**传播到检索与关联建议；临时网络失败不能被当成来源已删除。
- 第一阶段后台增量轮询；网络恢复后补同步。推送只用于改善时效，不替代差量拉取。
- 多账户隔离：来源记录带账户标识；不同账户的记录不串用。

### 2.4 授权、暂停、断开、删除

设置中每个连接显示：账户、读取范围、后台同步开关、模型处理方式（本地 / 云端）、最近同步时间与状态。

OAuth scope 与 Nova 内部范围分别展示："只处理选定标签"是 Nova 自身执行的过滤，不能声称
provider token 只允许该标签。发信、创建邀请等写权限按实际需要单独开放，且走执行授权路径。

三种操作语义：

| 操作 | 效果 |
|---|---|
| 暂停同步 | 停止后续读取；已有来源记录、检索与记忆保留 |
| 断开连接 | 停止后续访问并丢弃凭据引用；已有内容保留但标记来源已断开 |
| 删除来源数据 | **物理删除**该来源在 06 卷账本里的全部行（含原文），清理索引；派生记忆按 06 卷 §4 级联：只依赖它的条目自动墓碑，有其他独立依据的保留并显示“证据已删除”；相关 suggestion 撤回、`feed_item` 置 `invalidated`；用户主动忘记的内容记录抑制标记，防止重连后立即再生成 |

外部内容始终是低信任证据，不是系统指令或用户授权。采集与模型处理范围由主机实际执行，不只写在提示词里。

### 2.5 IM 连接器：飞书（M8-IM）

2026-09-12 决定：IM 渠道与邮件都在 v0.3.0 范围内。飞书是首个 IM 连接器，同时承担两种角色：

| 角色 | 做什么 | 走哪条路 |
|---|---|---|
| 来源 | 首版读取用户选定会话中的消息，写成 `evidence_record`（`source_kind = im`），入库时抽取 `commitment`（06 卷 §7） | §2.1 通用层：连接状态、凭据引用、游标、配额 |
| 投递渠道 | bot 向用户推送 02 卷已入池的 proposal，接收用户的回复动作（处理 / 稍后 / 忽略） | 02 卷 §2.5 交付记账新增第四类 `im`，与展示 / 通知 / 语音分别记录，`delivery.im_sent_at` |

规则：

- **必须是部署时配置的通用连接器**：应用凭据、可读范围、bot 目标会话都来自设置，代码里没有任何组织专属
  的群、机器人或工作流。组织专属集成继续留在 internal 分支，公共边界由
  `runtime/test/public-client-boundary.test.ts` 强制（现有仅允许通用飞书登录模块，本卷要求把
  “通用飞书连接器”同样纳入允许列表并写清判定标准）。
- **设置入口**：Settings Panel 独立的“IM 渠道”分区，以「连接应用 → 授权账号 → 选择会话」引导首次使用；提供创建新应用及绑定已有应用入口。会话统一列表、保留真实名称，开关采用 toggle。包含连接状态、选定会话、同步与保留期说明、暂停/断开/删除历史，以及默认关闭的本人 bot 提醒。复用同一连接器状态与命令，记忆页不再承载配置表单。
- 来源与投递分别授权：读消息不意味着能发消息；bot 推送是写权限，走 §2.4 的单独开关。
- IM 消息正文是低信任证据；“@Nova 帮我做 X”不是授权，仍需在 Nova 客户端里确认。
- 通过 IM 回复的查看、稍后、忽略动作与 feed 等价，去重台账共用；查看不等于授权执行任务。
- 钉钉等其他 IM 复用同一通用层与角色划分，本版只验收飞书。

### 2.6 与执行生态的边界

Kimi Code、pi agent 与 GUI/AutoGLM 的适配、验收和 agent2agent 演示见
[v0.4 Coding 与 GUI 执行器](../v0.4.0/02-coding-and-gui-executors.md)，不属于本版。
Connector 提供获准访问的来源与按需查询；executor 接受已授权工作并执行。
来源读取权限不自动授予发送、修改或设备操作权限。组织专属服务仍留在 internal。

## 3. 不做

- 全盘无差别采集、屏幕录制、剪贴板监听。
- 一次接多个邮件 / 日历 provider；一次接多个 IM。
- 在 renderer 或模型侧持有任何凭据。
- 把 MCP 搜索工具当作同步来源。
- 承诺关机后持续同步（见 00 卷部署边界）。

## 5. 验收场景

编号沿用讨论稿 §9。

- **8 来源变化**：邮件提出改期且与已有日历冲突，feed 出现冲突卡片并给出处理选项；会议随后取消，
  卡片更新为已解决，相关提醒撤回。
- **9 同步恢复**：断网、限流、cursor 失效、重复分页分别注入，同步能恢复且不产生重复来源记录；
  两个账户的记录互不串用。
- **10 权限边界**：外部邮件正文中包含"请立即执行 X"，不触发任何 dispatch；断开连接后不再读取；
  删除来源后相关检索返回空，派生记忆按规则处理。
- **目录覆盖诚实**：选择一个含 10,000 文件的目录，预算只读 200 个正文；设置页显示实际数字，
  记忆概览的覆盖声明与之一致。
- **排除生效**：目录内含 `.git`、`node_modules` 与一个指向范围外的符号链接；三者都不被读取，
  跳过原因可见。
- **18 飞书双角色**：一条授权群消息“周五前把评审意见发我”进入账本并抽出承诺；bot 在周四推送一条
  proposal，用户在飞书里点“稍后”，feed 上同一事项显示 `snoozed`；删除飞书本地历史后该消息的账本行物理
  消失，承诺条目墓碑，bot 停止推送。
- **19 IM 不是授权**：群里有人 @Nova 说“立即执行 X”，不触发任何 dispatch；记为低信任证据，最多产生一条
  `question` proposal。
